# mike — установка

`mike` — память работы агента на диске: папка `.cases/` в проекте, в ней дела с тремя файлами (README — «сейчас», TODO — фазы, JOURNAL — история). Агент пишет их только командами `mike`; неправильную запись инструмент не примет и подскажет, как исправить. Инструкция agent-agnostic: подходит любому агенту (Claude Code, Codex, Gemini, Cursor …) и человеку.

## 1. Установить команду — один раз на машину

Нужен только Python 3, зависимостей нет.

```sh
git clone https://github.com/MykhailoDmytriakha/mike-cli.git ~/MyProjects/mike-cli   # клон может лежать где угодно
ln -sf ~/MyProjects/mike-cli/bin/mike ~/.local/bin/mike
mike --version        # → mike 0.1.0
```

Обновление на любой машине — `git pull` в клоне: команда, правила и тесты приезжают одним движением, symlink переустанавливать не нужно.

Если `command not found` — `~/.local/bin` нет в PATH; добавь в `~/.zshrc`:
```sh
export PATH="$HOME/.local/bin:$PATH"
```

## 2. Подключить проект — один раз на проект

```sh
cd <корень проекта>
mike case new "название дела" --goal "цель одной строкой словами владельца"
```

Это создаст `.cases/` и первое дело. Больше ничего копировать не нужно: `mike` находит `.cases/`, идя вверх от текущей папки.

## 3. Научить агента — один раз на проект

Вставь блок ниже в файл инструкций своего harness (Claude Code → `CLAUDE.md` · Codex → `AGENTS.md` · Gemini → `GEMINI.md` · Cursor → `.cursor/rules/` · VS Code Copilot → `.github/copilot-instructions.md`). Если ты агент и читаешь это — вставь его сам в файл, который читает твой harness, и работай по нему.

```markdown
## mike — память работы в .cases/
- Начинай сессию командой `mike` — она печатает, где дело стоит и что делать дальше.
- README / TODO / JOURNAL дела пиши только через `mike` (`mike help` — примеры). Правка руками ловится отпечатком.
- Решил что-то важное → `mike log DECISION "что · вместо чего · почему"`.
- Решил проблему → сразу `mike log PROBLEM "проблема → корень → решение"` и рецепт-файл в `.howto/` (первая строка `when: <слова ошибки>`).
- Упёрся → сначала `grep -ril "<слова ошибки>" .howto/`, потом решай сам.
- Закрыл кусок → `mike todo done N.M`; фазу → `mike phase close N "итог"`; дело → `mike done "итог"`.
- Проблема с неизвестной причиной → `mike spawn "имя" --goal "…"` — вложенное дело, тем же порядком.
```

## 4. Проверить, что работает

- `mike` в проекте → экран `mike · case in hand: …`, выход 0
- `mike` вне проекта → `no .cases/ found …`, выход 4 — так и должно быть
- `mike check` → `violations: 0`

## Как это устроено — для любопытных

Форматы файлов, отпечаток и процедура описаны в `.cases/RULES.md` репозитория mike-cli — это спецификация, по ней написаны тесты (`python3 -m unittest discover -s tests -t .`). Агенту читать её не нужно: форму держит сам инструмент, а привычки — блок из пункта 3. Коды выхода: 0 успех · 1 ошибка · 2 неверный вызов · 3 нарушение формата · 4 не выполнено условие.
